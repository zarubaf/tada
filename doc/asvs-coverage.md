# OWASP ASVS 5.0 coverage

[ADR 0008](adr/0008-authentication.md) requires that tests cover the applicable requirements of OWASP ASVS 5.0 on authentication and session management.
The chapters are V6 Authentication and V7 Session Management of ASVS 5.0.0.
This file maps each requirement to the test that covers it.
A requirement that does not apply has the reason in its row.
The status "Partial" means that a test covers only a part of the requirement.
The status "Documented" means that the requirement asks for documentation and [ADR 0008](adr/0008-authentication.md) holds it.
The status "Manual check" means that the claim rests on a review of the code and no test proves it.

This file lists what exists today.
The rows for API tokens come with the API-token slice.

Test paths are relative to the repository root.
`sign_in.rs` means `crates/tada/tests/sign_in.rs`.

## V6 Authentication

tada has no passwords and no multi-factor authentication.
A member signs in with a one-time link that is sent to the email address of the member.
An invitation token creates the first sign-in.

## Related controls in other chapters

These controls are outside V6 and V7, but the sign-in tests also cover them.

| Control                                                                                                             | Test                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| The session cookie is `HttpOnly`, `Secure` and `SameSite=Lax`.                                                      | `sign_in.rs::a_member_signs_in_with_the_magic_link_in_the_organization`                                                 |
| A state-changing request needs a matching `Origin` header.                                                          | `events.rs::a_state_change_from_another_origin_changes_nothing`                                                         |
| A response forbids the referrer, so a token in a URL does not leak.                                                 | `sign_in.rs::each_response_forbids_the_referrer` and `invitations.rs::each_invitation_response_forbids_the_referrer`    |

| No log line holds an email address, a name, a token or a client IP address. The request log has the route template. | `support::logs::assert_clean` at the end of the tests in `sign_in.rs`, `invitations.rs`, `members.rs` and `telegram.rs` |
